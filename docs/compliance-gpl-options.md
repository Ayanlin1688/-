# 开源许可合规评估：PyQt5 / PyQt-Fluent-Widgets（供法务与采购决策）

> 非法律意见；以下为工程侧事实梳理与可选方案，最终请由法务确认。

## 一、事实（实测元数据）

| 组件 | 版本 | 当前许可 | 商业闭源分发影响 |
| --- | --- | --- | --- |
| PyQt5 | 5.15.11 | GPL v3（或 Riverbank 商业许可） | 闭源分发需商业许可，或改用 LGPL 替代（PySide6），或以 GPL 开源本应用 |
| PyQt-Fluent-Widgets | 1.11.3 | GPLv3（作者另售 Pro / 商业授权） | 同上；**其 PySide6 版同为 GPLv3**，仅换 PyQt 不能解决 |
| PyQt-Frameless-Window / requests / cryptography | 当前锁定版本 | BSD-3 / Apache-2.0 / Apache-2.0+BSD | 无阻塞 |

结论：**“全球商业发布（闭源收费）”在许可维度存在硬门槛，属发布首位阻塞项。**

## 二、可选方案对比

| 方案 | 工程成本 | 费用（需询价） | 风险 / 注意 |
| --- | --- | --- | --- |
| A. 购买商业许可 | 最低（零代码改动） | Riverbank PyQt 商业许可 + QFluentWidgets Pro（订阅制） | 需确认 QFluentWidgets Pro 授权条款覆盖桌面商用分发；预算随座位/产品数变化 |
| B. 迁移 PySide6 + 替换 UI 组件库 | 高（界面层 7k+ 行、猴补丁与自定义组件需重测） | 组件库替换若选 MIT/BSD 方案则近零许可费 | 工期：数周级；好处是彻底 LGPL + 长期自主 |
| C. 以 GPL 开源本应用 | 低 | 零 | 与应用“闭源售卖 + 拉投资”的商业模式冲突，基本不可行 |

## 三、建议路径

1. **立即**：向 Riverbank 与 QFluentWidgets 作者发起询价（邮件模板可含：桌面应用、闭源分发、预计 seats 数、是否需要再分发 OEM 条款）。
2. **并行**：工程师评估 B 方案的范围（划分“必换组件”清单：标题栏 / 导航 / 设置卡 / 消息条…），形成 2–4 周试点计划作为 Plan B。
3. A 方案落地前，分发范围限定为内部 / 试点客户（书面借用评估协议），避免规模化侵权风险。

## 四、给法务/上游的问题清单

- QFluentWidgets Pro 授权是否允许“编译进闭源桌面应用并按份售卖”？
- Riverbank 商业许可的再分发边界（OEM/白标）与续期条款？
- 若采用方案 B，现有代码（含对 GPL 库 API 的调用习惯）是否存在衍生作品争议点？
