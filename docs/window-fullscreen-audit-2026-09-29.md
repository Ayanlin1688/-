## 二、本次修复

### 1. 状态切换路径统一

- `ui/main_window.py` 将标题栏最大化按钮和标题栏双击统一接入 `_studio_toggle_maximized`。
- 禁用 QFluentWidgets 默认双击处理，避免默认行为与自定义窗口边距、按钮状态逻辑互相覆盖。
- 全屏状态下触发最大化/还原时先退出全屏，再进入明确的普通或最大化状态。

### 2. 视觉状态与 Qt 状态同步

- `QEvent.WindowStateChange` 触发窗口边距和最大化按钮同步。
- 全屏使用零边距，普通状态恢复 `_window_margin`，最大化状态保持边到边布局。
- `_sync_window_frame` 仅在几何确实变化时更新标题栏，减少重复布局和重绘。

### 3. 单实例唤醒不再破坏状态

- `main.py` 的单实例唤醒逻辑不再无条件调用 `showNormal()`。
- 最小化窗口会恢复到唤醒前的全屏或最大化状态；普通、最大化、全屏窗口均只执行显示、置前和激活。

### 4. 快速操作和 Windows 兜底

- 最大化切换保留代数校验，旧的延迟校验不会覆盖新的快速点击意图。
- 状态未按预期落地时执行已有 Win32 兜底，并再次同步窗口框架。

## 四、剩余风险

以下问题在本次窗口修复中未扩大修改范围，避免引入无关回归。

### P1：源码中仍保留共享密钥旧版许可格式

位置：`core/licensing.py:40`、`core/licensing.py:56`、`core/licensing.py:119`

YL1 使用内置 HMAC 共享密钥，源码运行环境可以生成和验证旧格式激活码。冻结发行版当前通过 `_legacy_hmac_allowed()` 拒绝 YL1，并优先使用 YL2 RSA 公钥验签，因此不构成本次窗口发布阻断；但如果源码被直接分发或以非冻结方式部署，许可可被伪造。

建议下一轮删除对外发码能力和共享密钥，或只保留离线迁移验证并设置明确的迁移截止版本。

### P1：UI 层宽泛异常捕获导致故障可见性不足

位置：`ui/main_window.py:114` 及该文件多个 `except Exception` 分支。

部分 UI 保护性分支直接吞掉异常，能够避免 Qt 槽函数中断，但也可能隐藏标题栏、布局、主题或页面初始化失败，使问题表现为“界面没有反应”。这类静默失败会增加后续窗口状态问题的定位成本。

建议把保护性异常收敛到明确的 Qt 生命周期异常类型，并至少写入脱敏日志；对关键状态同步失败应提供一次性诊断记录。

### P2：轮询超时存在默认值不一致

位置：`core/config_manager.py:27`、`core/task_execution.py:486`、`ui/pages/workspace_page.py:844`

配置默认轮询超时为 7200 秒，但任务执行和工作区观察逻辑的缺省回退值分别存在 7200/3600 秒差异。完整配置通常会覆盖回退值，但遇到旧配置、部分配置或迁移异常时，界面可能提前停止观察而后台仍在运行。

建议抽取单一共享常量，并增加“部分配置”场景测试，保证执行器和 UI 观察器使用同一截止时间。
