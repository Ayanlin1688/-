最大瓶颈：任务监看层缺位。「当前任务与实时进度」藏在「生成参数与任务详情」弹窗里，弹窗内容合计约 1030px，在 820px 高度内必须滚动才能看到进度卡；而主界面只剩一张表格在承担「监看」职责。顶级生产工具（Topaz Video AI、达芬奇、Runway）的第一屏永远是「队列 + 进度」，配置藏在后面。

  • 改造强度：布局重构（Layout Restructure）。保留深空主题视觉语言、三页信息架构与全部业务流；重排工作台的信息层次、工具栏组织、表格与日志规范。不到「全量重做」，也远不止「调调间距」。
  • 升级后骨架（目标稿已出）：顶栏只留状态与主操作 → 概览 4 主卡 + 复合卡 → 常驻「当前任务监看带」 → 目录配置行 → 任务队列（工具栏分组 + 规范表格）→ 日志区（筛选胶囊 + 图标操作）。
  • 实施原则：只动 ui/ 层会到「改哪、怎么改、怎么验」的程度；不动业务逻辑与主流程。每批改完用「截图对比 + 全量回归」验收。

02评审方法与素材

三个视角互相校验，避免只凭观感下结论。

  • 逐屏设计评审（8 个场景）：工作台空态 / 任务态 / 展开导航态、当前任务卡、任务队列卡特写、历史页、设置两页、日志展开态。每屏按「布局结构、间距、对齐、字号层级、留白密度、截断与错位」逐条过，问题按高 / 中 / 低定级。
  • 几何实测（硬数据）：对关键组件做渲染级测量（位置、尺寸、内外边距、字号、行高），共 50 余项数值，用来区分「观感问题」与「实际数值问题」。
  • 代码基线核对：所有结论与当前实现的组件结构逐一对得上（布局容器、表格列规格、主题 token），确保改法可落地。

评审覆盖的核心场景：工作台（空态 / 任务态 / 展开导航）、任务队列与当前任务区、任务历史、设置（默认页 / 外观页）、执行日志（收起 / 展开）。原始截图与评审记录见第 09 节素材索引。

03诊断：五个根因

把 40 多条散点问题归拢到 5 个根因，改造按根因走，不做逐条打补丁。

根因 A · 信息层级扁平，字号阶梯缺失贯穿全部页面

全界面在 10–12px 区间堆了绝大多数文字：概览卡的标签约 12px、数值仅 26px 高；表头与正文几乎同号，只靠颜色区分；日志 11.5px 且对比度偏低。没有清晰的「大数值 / 标题 / 正文 / 辅助」四级阶梯，扫读时抓不到重点。深色背景下辅助灰字（#7C8596 一档）在低亮度屏幕上读起来费劲。

根因 B · 操作无主次，工具按钮平铺任务队列头部 / 日志头部 / 顶栏

任务队列头部同排 5 个操作（全部状态筛选、重置模型识别、生成参数、匹配详情、取消全部），视觉权重完全相同；「取消全部」这种破坏性操作没有任何样式区分与二次确认。日志头部同样挤了 8 个控件（5 个筛选 + 导出 + 清空 + 展开）。顶栏「未配置 / 自动保存 / 暂停 / 开始生成」混排，前置条件未满足时主按钮的可用逻辑不清晰。

根因 C · 表格对齐与状态规范缺失任务队列 / 历史页

文本、数值、状态混用同一种对齐方式；历史页时间列折行、文件大小小数点不对齐；任务队列进度条仅 87px 宽且百分比位置随数值浮动，竖向无法比较；状态标签样式不统一（实底 / 描边 / 虚框混用）；序号列的彩色圆点与状态列语义重复，等于同一信息表达两遍。

根因 D · 重复信息占位，密度分配失衡工作台全域 / 设置页

「产品 / 任务进度」在顶栏状态条、概览卡、队列头部、日志头部出现 4 次；「匹配详情」入口出现 2 次；设置页主标题与卡片内小标题重复、说明文案两段重复。与此同时，任务队列行高 52px 信息密度却不低，日志区默认高度只有 140px，形成「该松的不松、该紧的不紧」。

根因 E · 任务监看层缺位（本轮最核心）工作台信息架构

实测：「当前任务卡 + 参数卡 + 数据源卡 + 最近完成」总高约 1030px，全部放在「生成参数与任务详情」弹窗（980×820）内，且弹窗内还要滚动；主界面只有概览数字和表格在承载监看。结果是：想确认「现在跑到哪了、还剩多久」必须开弹窗，这对一个「挂着跑批」的生产工具是结构性问题。顶级工具的第一屏结构是「队列 + 当前任务进度」常驻，配置抽屉化，这个骨架需要补上。

06升级方向与边界

先划边界再动手：哪些绝不碰、哪些可以重构、做到什么强度。

必须保留（不动）
  • 深空主题视觉语言：深底 + 玻璃卡 + 蓝紫强调色（全部主题保留）
  • 三页信息架构与导航方式（工作台 / 历史 / 设置；折叠与展开两态）
  • 业务主流程与全部功能入口（扫描→匹配→生成→下载、重试、待确认处理）
  • 品牌元素与既有文案语义（可优化措辞，不改含义）
  • 不改业务逻辑、路由与数据模型
可以重构
  • 工作台信息层次与区域顺序（监看层上桌、概览减值分级）
  • 工具栏组织（分组、更多菜单、危险操作样式）
  • 表格系统（对齐规则、列宽、状态胶囊、进度列、行样式）
  • 日志区排布与对比度；设置页间距、侧栏层级与卡片规范
  • 弹窗信息架构（瘦身、去滚动、配置归位）

设计方向（一句话）：把它当作一台「长期挂机的生产控制台」来排版：先监看、后配置；信息密度保持高，但用字号阶梯与对齐规则让每一眼都有落点。强度：布局重构，分三批实施，每批独立可回退。

目标

把 CurrentTaskCard 的进度区抽为一个紧凑横条组件，挂到工作台 splitter 上方（目录行与队列之间）；完整卡片仍留在弹窗作详情。
文件

低。纯增量组件，不改现有卡。
验证

08验收与实施节奏

沿用本项目「改一批、验一批、推一批」的节奏。

  • 批次 1（P0）：布局骨架四项。验收 = 工作台三态（空 / 运行 / 展开导航）截图对比 + 全量回归 + 真实点击冒烟。
  • 批次 2（P1）：规范层四项。验收 = 表格四档宽度对齐实测 + 历史 / 设置 / 日志截图对比 + 全量回归。
  • 批次 3（P2）：打磨三项。验收 = 对比度清单 + 空态 / 禁用态截图 + 弹窗流程冒烟。
  • 每批通用门槛：视觉改动的文件在提交信息里逐项列出；任何交互行为变化（如取消确认）同步补 UI 测试；批次结束更新本方案状态。

整体估时（含验证）：批次 1 约 1 天、批次 2 约 1–1.5 天、批次 3 约半天。三项都不改业务逻辑，可独立回退。
